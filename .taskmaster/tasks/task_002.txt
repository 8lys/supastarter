## 1. Define common User and Session interfaces [pending]
### Dependencies: None
### Description: Create standardized interfaces for User and Session objects that will work across all auth providers. Ensure these interfaces contain all necessary fields while abstracting provider-specific details.
### Details:
Define TypeScript interfaces for User (id, email, name, etc.) and Session (user, token, expiresAt, etc.) that can be implemented by both Better-Auth and Supabase. Consider existing usage patterns in the application to ensure backward compatibility. Include proper JSDoc comments for all interface properties.

## 2. Define AuthError types and error code system [pending]
### Dependencies: None
### Description: Create a unified error handling system with consistent error codes that work across providers. Define the AuthError class structure and standardize error codes for common auth failures.
### Details:
Design an AuthError class with properties for code, message, and optional cause. Create an enum of stable error codes (e.g., INVALID_CREDENTIALS, EMAIL_NOT_VERIFIED, SESSION_EXPIRED) that will remain consistent regardless of the underlying provider. Map provider-specific errors to these standardized codes. Document each error code with expected scenarios and recommended user-facing messages.
